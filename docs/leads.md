# 新的切口（D90 → D780 通用这一事实带来的线索）

前提：同一份 `NKLD????.BIN` 从 D90（2008）一直用到 D780（2020），相机内显示为 `L 2.0xx`。
这意味着**解混淆/解析逻辑必须存在于所有机身**，包括最早、最小、防护最弱的 D90。围绕这一点做了
一轮新探测，记录如下。

## 1. 尾部条目是“按代追加”的（已证实）

对比 2.017 与 2.018 的 52 字节条目：

```
2.017: entry0, entry1, entry2
2.018: entry0, entry1, entry2, entry3   # 前三条逐字节相同，只多出 entry3
```

这与“每新增一代机身就追加一条 52 字节块”的行为一致（2.013 对应 D5/D500 一代，2.018 对应
2019 年的 D3500/D5600 一代），而不是整体签名。52 字节块可能是按世代的参数/兼容块，值得作为
“机身世代 → 解释方式”的索引继续挖。

## 2. D90 固件是半明文，且包含 L 数据的入口

下载并解包了 `F-D90-V101W.exe` → `D90_0101.bin`（7,864,322 B，SHA-256 见文末）。它是**未加密**
的固件（至少资源区是明文），可以直接看到：

| 偏移 | 内容 |
| --- | --- |
| `0x08` | `D90  Firmware A Copyright Nikon Corp.` |
| `0x1ACFA4` | 魔数 `87 C7 CA AC`（与 NKLD 头同一个魔数） |
| `0x21305E` | `NKLD????.BIN`，前后是 `S???????.BIN`、`D90_????.BIN`、`BD90????.BIN`、`AD90????.BIN` |
| `0x213000` | 一串 32 位文件偏移（`0x169474`、`0x16947C`…），指向代码/数据结构 |

这说明 D90 确实有 L 数据入口。但 D90 的代码不是 ARM/Thumb（四种模式反汇编都不成立），从指令
形态看很可能是 **Fujitsu FR 大端**（与 firmware_notes 里 D5100/D3200 的 “FR BE” 一致），
或者代码区被压缩。要往下走需要 FR 反汇编器或先解压。

## 3. D7200 解密镜像同样有入口，但没有密钥

`D7200_0104.dec`（19.6 MB）里：

- `NKLD????.BIN` 在 `0x11CC7F2`；
- 魔数的小端字面量在 `0x15B1C9`、`0x15B681`、`0x1B330D`；
- 用恢复出的 108×u16 密钥序列（允许逐位取反、全对齐、大小端、u16/u32 步长）扫描：**无命中**。

## 4. 密钥不在任何手头镜像里（负结果汇总）

| 镜像 | 大小 | 结果 |
| --- | --- | --- |
| `b1010_115a.bin`（D750 主） | 20.3 MB | 无 |
| `a1010_011100.bin`（D750 引导） | 0.79 MB | 无 |
| `eg1510_012100.bi`（D780 主） | 35.6 MB | 无 |
| `b860_102.bin`（D3300 主） | 23.9 MB | 无 |
| `D7200_0104.dec`（D7200 解密） | 19.7 MB | 无 |
| `D90_0101.bin`（D90） | 7.9 MB | 无（明文区） |

最长连续匹配 1~2 个值，与随机无异。密钥不是以明文表存放在这些镜像里。

## 5. 可继续试的切口（按性价比排序）

1. **FR 反汇编 D90**：D90 是最老的 L 2.x 载体，代码量小、资源明文。只要能把
   `0x169474` 附近和 `NKLD` 入口的 FR 代码读出来，就可能看到 L 数据的解析/解混淆流程。
   需要 FR/FR-V 反汇编器（Ghidra 有 FR 插件，或自写 16 位指令表）。
2. **WMA_ 容器做已知明文对**：WLAN 固件在机身里是 DfuSe（`_wma_ver01.11.00`，明文，882,985 B），
   而 SD 卡上的 `WMA_????.BIN` 走的是与 NKLD 相同的魔数容器。如果能拿到一份 `WMA_` 更新包，
   就有“明文 DfuSe 镜像 + 同格式容器”的已知明文对，可反推这类容器的 XOR 流，验证是否与 L 数据
   共用同一套方案。
3. **老版本 L 数据（2.000/2.009/2.013）**：条目数应更少。若早期版本的记录没有混淆、或混淆
   参数不同，就能看出混淆是何时引入的；镜像站（touslesdrivers 等）还留有 2.013。
4. **服务模式/PTP 读数**：D3300 调试符号里有 `CPTPCGetLensDataFlashRead` /
   `CPTPCSetLensDataFlashWrite`，说明相机可以通过 PTP 读 L 数据 flash。读出来的明文就是
   “已知明文真值”，能一举定掉 4 重符号歧义（需要一台可连的机身）。
5. **找嵌入式出厂 L 数据**：相机出厂时 flash 里应有一份 L 数据（旧版本）。若某个 boot/资源区
   存的是明文镜像，就能直接和官方文件做已知明文攻击。目前 b1010/a1010/b1330 只找到代码字面量，
   没找到镜像，值得在压缩资源里继续找。
